# AGENTS.md

This file provides guidance to agents when working with code in this repository.

Municipal portal demo built with SvelteKit 3 / Svelte 5 / Tailwind 4 / TypeScript and PostgreSQL 17 (Drizzle). See `README.md` for setup and `docs/engineering-brief.md` for feature-area conventions.

## Commands

- Use `npm` (`.npmrc` has `engine-strict=true`). Don't edit `package.json` by hand.
- `npm run dev` uses port 5180 with strict port selection. Never stop another project's dev server.
- `npm run check` = `svelte-kit sync && svelte-check`; this is the typecheck. Run it after changing routes, because `./$types` is generated by `sync`.
- `npm run lint` = `prettier --check . && eslint .`; `npm run format` fixes formatting.
- Lint a single file: `npx eslint path/to/file.svelte` and `npx prettier --check path/to/file`.
- **No test framework is installed.** Run the small assert-based `*.check.ts` scripts with `npx tsx`; see `docs/verification.md`. Runtime checks require the seeded database and a running server. `db:seed` and `db:setup` erase demo data; don't run them against existing work without permission.

## Code style

- Prettier: tabs, single quotes, no trailing commas, width 100. Tailwind class order is auto-sorted using `src/routes/layout.css` as the stylesheet. `package-lock.json` and `/static/` are prettier-ignored.
- Runes mode is forced for all non-`node_modules` code in `vite.config.ts`. Use `$props()`, `$state`, `$derived` and `{@render children()}`. Do not use `export let`, `$:` or `<slot>`.
- Svelte components use `<script lang="ts">`. Type props with generated types, e.g. `let { children }: LayoutProps = $props();` (imported from `./$types`).
- Shared code lives in `src/lib/`. Import it through the package-`imports` alias `#lib` or `#lib/*` (e.g. `#lib/assets/favicon.svg`), not `$lib`. The alias is defined in `package.json`, not `tsconfig`.
- Tailwind is v4 and CSS-first. There is no `tailwind.config`; plugins (`forms`, `typography`) are registered with `@plugin` in `src/routes/layout.css`. That file is imported from `+layout.svelte`.
- ESLint uses `recommendedTypeChecked`, so type-aware rules apply (`projectService: true`). `no-undef` is off. ESLint ignores whatever `.gitignore` ignores.
- The adapter is `adapter-node`, configured in `vite.config.ts`. Run the built server with `node --env-file=.env build`; see the README for host, port, origin and upload limits. Authentication and external integrations remain demo-only.
